# 模块化开发任务包

任务包以模块边界为单位，采用“直接重构、按阶段删除旧实现”的策略。

## 执行原则

1. 新模块只依赖 Domain、Ports 和明确的上游模块；
2. 不保留无价值的旧目录兼容层；
3. 旧模块只有在新模块测试通过后删除；
4. 数据库 Schema、知识写入和索引构建分别交付；
5. 每个任务包都必须有可运行的验收结果。
