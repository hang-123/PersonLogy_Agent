# P10-C 血缘与回溯开发计划

## 目标

建立不修改业务事实表的 `LineageLink` 追加式记录，并提供按稳定实体 ID 回溯来源、任务、审核、索引和检索结果的只读查询能力。

## 阶段

- [x] 盘点现有实体 ID、派生边界和查询入口
- [x] 实现 `LineageLink` 领域模型、端口和 SQLite 存储
- [x] 接入编译、治理、审核、索引、检索派生关系
- [x] 实现 Claim、SourceVersion、Job、RetrievalRequest 四类回溯查询
- [x] 补充项目隔离、幂等、方向和异常路径测试

## 关键决策

- 血缘关系采用有向边：`from_type/from_id -> to_type/to_id`。
- 关系写入追加式、幂等，不覆盖历史边；重复边不产生重复记录。
- 血缘查询只读，必须按 `project_id` 做租户边界过滤。
- 原文不写入血缘元数据；只保存实体 ID、关系类型、版本和摘要字段。
- P10-C 复用 P10-B 的 `AuditSink`、`TraceContext` 和摘要规则，不重新实现审计链。

## 当前状态

已完成：统一血缘模型、SQLite 存储、核心服务接入、四类回溯查询、API 路由和测试验收均已落地。
