# P10-D 监控投影开发计划

## 目标

基于 P10 审计事件增量生成低基数指标快照，支持 checkpoint、失败重放和健康检查，使本地 SQLite 环境可以判断任务失败、队列积压、索引过期、审计链异常和工具未知态。

## 范围

- `MetricsProjector`：按审计序列增量消费事件并更新派生指标；
- checkpoint：记录已处理序列，支持从上次位置继续；
- 失败重放：记录投影失败事件，并支持从失败序列重新投影；
- `MetricsSnapshot`：保存低频、低基数聚合快照；
- 健康快照：合并指标投影、队列积压、索引新鲜度、数据库和审计链状态；
- 只读 metrics/health API；
- `StageRunner` 继续作为阶段耗时/成功/失败事件唯一入口。

## 关键决策

- 指标是审计事件的派生投影，不新增业务侧重复计数器。
- 投影表只保存低基数标签；不保存原文、Prompt、完整错误和用户输入。
- 失败事件不自动跳过：checkpoint 停留在失败序列，修复后通过 replay 继续推进。
- 队列积压、索引新鲜度、数据库连接和审计链完整性属于健康快照的运行时检查，不伪装成审计事件。
- SQLite 是本阶段适配目标；Prometheus/OpenTelemetry exporter 留到 P10-F。

## 退出标准

- 可从审计序列增量生成任务失败率、阶段耗时、工具未知态等指标；
- 投影重启可从 checkpoint 继续，失败事件可重放；
- `/metrics` 和 `/health/ready` 能返回队列、索引、数据库、审计链和投影状态；
- 指标标签经过低基数约束，测试确认不写入敏感原文。

## 当前状态

已完成：指标模型、事件投影、checkpoint、失败重放、健康快照、API 接入和验收测试均已落地。

## Errors Encountered

- 初版批量补丁因 PowerShell/JavaScript 引号嵌套失败，已拆分为领域、适配器和应用层补丁后完成。
- 健康测试初始把单个历史任务失败视为整体降级，已收敛为由队列积压、索引过期、审计链异常、数据库不可用或投影失败触发降级；失败率作为独立指标返回。
