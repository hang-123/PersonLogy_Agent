## 二、推荐开发顺序

优先完成一条纵向切片：

```text
PDF 上传
→ MinIO 保存
→ PDF 解析
→ ContentBlock
→ LLMWiki 编译
→ Claim + Citation
→ Gel 写入
→ 全文检索
→ 返回原文页码
```

完成这条链路后，再加入 Relation、向量检索、对话导入和前端关系图。

## 四、阶段质量门槛

### 数据正确性

- 重复导入不产生重复来源；
- SourceVersion 使用内容哈希区分；
- 原始资料不可变；
- ContentBlock 能回到 PDF 页码或对话消息；
- 删除和更新不会静默破坏引用。

### 知识正确性

- 每个 Claim 都有 Citation；
- Relation 有类型、方向和状态；
- 重要 Relation 有证据；
- 机器生成和人工确认状态分离；
- Schema 不匹配时进入变更审批，而不是直接写入。

### 检索质量

- 全文、向量和关系检索可以组合；
- AI 只能访问授权项目；
- 回答可以返回证据片段；
- 冲突来源能够被标识；
- 索引可以从 Gel 主数据重新构建。

## 五、重构策略

1. 先建立测试基线，再移动代码；
2. 先抽取领域模型和端口，再替换基础设施；
3. 先实现 PDF 单链路，再迁移对话和旧功能；
4. API 路由不直接操作 Gel 或 LLM；
5. 不一次性拆微服务；
6. 每个阶段保留可运行版本；
7. Schema Migration、知识写入和索引构建分别审计。
