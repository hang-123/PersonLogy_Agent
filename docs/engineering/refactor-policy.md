# 旧代码重构与删除策略

## 总原则

PersonLogy 采用直接重构，不以旧目录结构为约束，不为失效实现长期保留兼容层。

## 执行规则

1. 先确认旧代码的入口、调用方和测试覆盖；
2. 按任务包重写目标模块；
3. 新模块具备最小可运行验收后，删除旧实现；
4. 旧代码不与新代码长期双写；
5. 仅当外部 API 合同仍需保持时，保留薄适配层；
6. 删除前记录删除原因和替代模块；
7. 每个任务包单独提交，便于回溯。

## 可以直接删除的内容

- 未被入口引用的旧模块；
- 已被新 Adapter 替代的外部服务实现；
- 重复的工具类、旧版 Prompt 和废弃 DTO；
- 与新领域模型冲突的旧数据库访问代码；
- 仅为旧目录结构存在的转发层。

## 不应直接删除的内容

- 尚未确认来源的数据库迁移；
- 当前生产数据或原始文件；
- 尚未建立替代测试的关键行为；
- 仍被前端或外部调用的公开 API。

## 删除检查

- `rg` 检查引用关系；
- 单元、集成和端到端测试通过；
- 数据库迁移和备份可恢复；
- 任务包验收标准通过；
- 代码审查确认无隐藏入口。
