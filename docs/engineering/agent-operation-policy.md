# 开发协作约定：命令行操作边界

> 适用：任何在本仓库工作的 Agent / 协作会话。请先阅读本文，再执行命令。

## 约定

**以下操作默认不直接执行**，而是给出完整操作步骤、预期结果与风险说明，由开发者
本人确认后在真实终端执行：

- 数据库**建库 / 删库 / 清库 / 迁移生成与应用**（Gel migration create/migrate、
  `configure database`、`database wipe`、DROP 等）；
- 需要**系统级权限**的操作（安装系统软件、修改 PATH / 注册表 / 服务、写系统目录）；
- **不可逆或有副作用**的命令（批量删除、覆盖生产/共享数据、重置实例）；
- **结果不确定**的实验性命令（交互式 CLI、需要人工确认决策的流程）。

这类操作往往：① 需要高权限；② 流程长且步骤间有依赖；③ 出错会影响数据与环境。
由开发者亲自动手可以即时看到输出、按需调整，也避免自动化误操作。

## Agent 侧行为

- 识别到上述操作时，输出：**背景与目标 → 具体命令（可直接复制）→ 预期结果 →
  已知风险/坑 → 验证方法**，然后停下来等开发者执行；
- 不要自行"绕过"或尝试等价替代命令去达成同一目的（例如用驱动 API 代替 CLI 建库）；
- 只读检查（`gel query` 只读、查看迁移状态、查数据）和普通代码改动、测试、静态检查
  照常执行；
- 开发者明确要求 Agent 执行时，仍按本文约定先说明再执行，除非开发者明确豁免。

## 开发者侧受益

- 对数据库/环境拥有完全掌控，可即时观察输出；
- 高风险命令有 Agent 提供的核对清单，减少误操作；
- 另一台设备（无 Gel 环境）按文档即可复现，不依赖 Agent 的执行权限。

## 已按本约定移交的操作（示例）

  配置 —— 命令见 `GEL/README.md`，本机已由开发者/Agent 协作完成。
